# ZONE — Milan Mini App

منصة بث رياضي (Telegram Mini App) — واجهة أمامية Vanilla JS، بروكسي بث عبر Cloudflare Workers
و Supabase Edge Functions، وقاعدة بيانات/لوحة تحكم على Supabase.

> ⚠️ **إعادة هيكلة الملفات (بدون أي تغيير في المنطق أو السلوك):**
> كل ملفات CSS/JS كانت سابقًا مضمّنة داخل وسوم `<style>`/`<script>` بملفات HTML ضخمة
> (`player.html` كان فيه سكربت واحد بـ١٨٠٠+ سطر). تم فصلها بالكامل لملفات خارجية مقسّمة
> حسب المسؤولية، مع الحفاظ على **نفس المحتوى حرفيًا وبنفس ترتيب التنفيذ** (تم التحقق آليًا
> عبر مقارنة كل ملف مقسّم بمحتوى الأصل قبل الفصل — صفر فرق). الهدف: تقليل حجم كل ملف
> عشان يسهل القراءة والتعديل بدون فتح آلاف الأسطر لتغيير دالة وحدة.

## ترتيب تحميل سكربتات المشغّل (مهم عند التعديل)

ملفات `js/player/01..10` هي سكربتات عادية (لا modules) تُحمّل بالترتيب داخل `player.html`
وتتشارك نفس النطاق العام (global scope) — تمامًا مثل ما كانت تتصرف وهي سكربت واحد. **الترتيب
في `<head>`/`<body>` لازم يبقى كما هو**، لأن ملفات لاحقة تستخدم دوال ومتغيرات معرّفة بملفات سابقة
(مثال: `06-load-source.js` يستدعي دوال من `05-engines.js` و`04-stream-detect.js`).

نفس المبدأ لملفات `js/admin/01..09`.

## قاعدة عامة لإضافة كود جديد

- كود يخص **عرض/تنسيق فقط** → `assets/css/*.css`
- منطق جديد يخص محرك تشغيل أو بروكسي → `js/player/04-*` أو `05-*`
- منطق واجهة لوحة التحكم → أقرب ملف بـ`js/admin/` حسب الوظيفة، أو ملف جديد إذا الوظيفة مستقلة
- لا تُرجع الكود لملف HTML مضمّن — حافظ على الفصل حتى لا نرجع لملفات ٢٠٠٠+ سطر
